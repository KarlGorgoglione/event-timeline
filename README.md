# event-timeline

A Canvas-based, domain-agnostic timeline library for the web, with a React
binding. It renders **elements** (horizontal lanes) and **events** (directed
arrows between lanes at a point in time), and holds 60 fps at 50,000 events on
a GPU-backed WebGL2 renderer, with Canvas2D as the fallback.

**▶ [Live demo](https://karlgorgoglione.github.io/event-timeline/)** · [API
reference](https://karlgorgoglione.github.io/event-timeline/api/) · [Design
specification](docs/DESIGN.md) · [Decision records](docs/adr/README.md)

| [`@event-timeline/core`](packages/core/README.md)   | Framework-free engine (pure TypeScript).    |
| [`@event-timeline/react`](packages/react/README.md) | React binding: `<Timeline />`.              |
| `examples/demo`                                     | Vite playground, perf harness, e2e fixture. |

## Install

```bash
# React apps (the binding brings the engine and re-exports its API):
pnpm add @event-timeline/react

# Any framework, or none:
pnpm add @event-timeline/core
```

## Development

Requires **Node ≥ 22** and **pnpm** through Corepack (`corepack enable pnpm`).

```bash
pnpm install
pnpm dev          # the demo at http://localhost:5173
```

| Command              | What it does                                                       |
| -------------------- | ------------------------------------------------------------------ |
| `pnpm build`         | Build both packages (ESM + CJS + types).                           |
| `pnpm typecheck`     | `tsc --noEmit` in every package.                                   |
| `pnpm lint`          | Type-aware ESLint (with package-boundary rules) + Prettier check.  |
| `pnpm test`          | Vitest unit suites (core, react, demo).                            |
| `pnpm test:coverage` | The same, with coverage thresholds.                                |
| `pnpm test:e2e`      | Playwright: interaction (Chromium, Firefox, WebKit), golden, perf. |
| `pnpm size`          | Bundle-size budgets.                                               |
| `pnpm docs:api`      | Generate the API reference with TypeDoc into `docs/api/`.          |

Playwright needs its browsers once:
`pnpm exec playwright install --with-deps chromium firefox webkit`. Pick suites
with `--project`: `interaction`, `interaction-firefox`, `interaction-webkit`
(opt-in on Windows with `E2E_WEBKIT=1`), `golden` (Linux baselines), `perf`
(Canvas2D budgets) and `perf-gpu` (WebGL2 on the GPU, Gate 2). Golden
baselines are regenerated by the **Update golden screenshots** workflow; perf
runs nightly on main (see [ADR 0009](docs/adr/0009-perf-gating.md)).

## Releasing

Versioning uses [Changesets](https://github.com/changesets/changesets): add a
changeset with `pnpm changeset` in the pull request. After CI passes on main,
the release workflow keeps a **Version Packages** pull request up to date;
merging it publishes the new versions to npm.

Publishing is **tokenless**: npm Trusted Publishing (OIDC) lets the release
workflow mint a short-lived credential, so there is no `NPM_TOKEN` secret and
nothing can be published from a laptop. Each package has a Trusted Publisher
configured on npmjs.com for this repository and `release.yml`. See
[ADR 0008](docs/adr/0008-release-pipeline.md). The demo is private and never
published.
